## 소프트웨어 설계 문서 (Software Design Document)

### 1. 개요 (Overview)

이 문서는 Python 기반의 P2P(Peer-to-Peer) 마피아 게임 프로젝트의 설계와 아키텍처를 설명합니다. 본 프로젝트는 한 명의 인간 플레이어와 다수의 AI 에이전트가 함께 플레이하는 환경을 목표로 하며, 핵심 기술로 **동형암호(Homomorphic Encryption)**를 사용하여 중앙 서버 없이도 게임의 주요 로직(투표, 역할 확인 등)을 신뢰가 필요 없는(Trustless) 방식으로 안전하게 처리하는 것을 목표로 합니다.

각 플레이어(AI 에이전트)는 독립적인 `FastAPI` 서버로 동작하며, 게임의 상태를 관리하고 다른 플레이어와 상호작용하는 P2P 네트워크를 구성합니다.

이 문서는 신규 개발자의 온보딩을 돕고, 현재 아키텍처의 한계점을 명확히 하며, 향후 개발 방향을 제시하기 위해 작성되었습니다.

---

### 2. 시스템 아키텍처 (System Architecture)

본 시스템은 크게 3가지 주요 컴포넌트로 구성됩니다.

| 컴포넌트 | 핵심 파일 | 역할 및 책임 | 현재 상태 |
| :--- | :--- | :--- | :--- |
| **1. 게임 호스트 (Game Host)** | (존재하지 않음) | - 게임 시작 및 종료 관리<br>- 게임 규칙에 따른 낮/밤 사이클 진행<br>- 플레이어(에이전트)들의 API를 호출하여 게임 로직(투표, 암호화 연산 등)을 조율<br>- 인간 플레이어의 인터페이스 제공 | **미구현** |
| **2. 플레이어 에이전트 (Player Agent)** | `player.py`, `security.py`, `agent_logic.py` | - 개별 플레이어의 상태(`AgentState`) 관리<br>- `FastAPI` 기반의 API 서버 역할<br>- 분산 키 생성(DKG) 및 공동 복호화 등 동형암호 프로토콜 참여<br>- 게임 상황에 맞춰 AI 로직(`agent_logic.py`)을 통해 행동 결정 | **구현됨** |
| **3. 로비 서버 (Lobby Server)** | `lobby.py` | - AI 플레이어 에이전트(`player.py` 프로세스)들을 생성하고 관리 | **구현됨** |

```
|                                 |   |                       |   (FastAPI Server @ player.py)  |
|       Lobby Server              |   |                       |                                 |

|                                 |   |                        
+---------------------------------+   |                       .
                                      |                       .

                                      |   (HTTP Requests)     +---------------------------------+

                                                              |      Player Agent N (AI)        |
                                                              |   (FastAPI Server @ player.py)  |
                                                              |                                 |
                                                              +---------------------------------+
```

#### 2.2. 핵심적인 문제: 게임 호스트의 부재

현재 코드베이스에서 가장 시급하고 중대한 문제는 **게임 호스트(Game Host)가 존재하지 않는다**는 점입니다. 게임의 전체 흐름을 조율하고, 플레이어들의 행동을 요청하며, 게임의 규칙을 적용하는 중앙 지휘자 역할의 컴포넌트가 완전히 누락되어 있습니다.

따라서 **가장 먼저 해야 할 일은 이 게임 호스트를 구현하는 것**입니다.

### 3. 동형암호(HE) 설계

본 프로젝트의 가장 큰 기술적 특징은 `openfhe-python` 라이브러리를 사용한 동형암호 기반의 'Trustless' 모델입니다. 이는 중앙 서버가 개별 플레이어의 역할이나 투표 내용을 알 수 없도록 보장합니다.

**주의:** `requirements.txt`에는 `tenseal`이 명시되어 있으나, 실제 `security.py`에서는 `openfhe-python`을 사용하고 있습니다. 이는 반드시 수정되어야 합니다.

#### 3.1. 현재 구현 상태

- **암호화 컨텍스트 (`security.py`):** `create_openfhe_context` 함수를 통해 동형암호 연산을 위한 기본 환경(BFVrns 스킴)을 설정합니다.
- **분산 키 생성 (Distributed Key Generation - DKG):**
    - 플레이어들은 `dkg_keygen_join` 함수를 통해 각자 키의 일부(`partial_key`)를 생성합니다.
    - 게임 호스트(가 될 컴포넌트)는 이 조각들을 모아 하나의 공동 공개키(Collective Public Key)를 생성하고, 이를 모든 플레이어에게 배포해야 합니다. 이를 통해 어떤 단일 개체도 전체 개인키를 소유하지 못하게 됩니다.
- **공동 복호화 (Collaborative Decryption):**
    - 암호화된 결과(예: 투표 합산 결과)를 복호화할 때, 각 플레이어는 `partial_decrypt_main` 함수를 통해 자신의 키 조각으로 부분적인 복호화를 수행합니다.
    - 게임 호스트는 이 부분 복호화 결과들을 `fusion_decrypt` 함수로 취합하여 최종 결과를 얻습니다.
- **암호화된 연산 (`security.py`):**
    - `create_one_hot_vector`: 플레이어의 선택(예: 투표 대상)을 암호화된 '원-핫 벡터'로 만듭니다. 예를 들어 2번 플레이어를 지목하면 `[0, 1, 0, ...]` 벡터를 암호화합니다.
    - `compute_killed_vector`: 암호화된 투표 벡터들을 동형암호적으로 합산하여(homomorphic addition) 누가 가장 많은 표를 받았는지 계산합니다.

### 4. 마피아 게임 규칙 분석

현재 구현된 코드는 표준 마피아 게임의 일부 규칙만을 포함하고 있으며, 많은 부분이 미구현 상태입니다.

#### 4.1. 구현된 규칙/기능

- **역할:** `models.py`의 `Role` Enum을 통해 `MAFIA`, `POLICE`, `CITIZEN` 역할이 정의되어 있습니다.
- **AI 행동 결정:** `agent_logic.py`는 AI 에이전트가 자신의 역할과 게임 상황에 따라 프롬프트를 생성하여 행동을 결정하는 로직의 기반을 마련하고 있습니다.

1.  **[CRITICAL] 게임 흐름의 부재:** 게임 호스트가 없어 낮/밤 사이클, 투표 절차, 승리/패배 조건 확인 등 게임의 핵심적인 흐름이 전혀 구현되어 있지 않습니다.
2.  **[TODO] 직업 능력 미구현:**

### 5. 온보딩 및 개발 로드맵

#### 5.1. 프로젝트 설정 및 실행

1.  **의존성 설치:**
    ```bash
    # 먼저 requirements.txt 파일의 내용을 수정합니다.
    # "tenseal" 라인을 삭제하고 "openfhe-python"을 추가하세요.
    pip install -r requirements.txt
    ```
2.  **로비 서버 실행:**
    ```bash
    # 새 터미널에서 로비 서버를 시작합니다.
    ./start_lobby.sh
    ```
    이 스크립트는 `lobby.py`를 `uvicorn`으로 실행하여 AI 에이전트를 생성할 준비를 합니다.

3.  **게임 플레이 (현재 불가):**
    - 위에서 설명했듯이, 게임 호스트가 없으므로 현재 상태에서는 실제 게임을 플레이할 수 없습니다.

#### 5.2. 개발 로드맵 (단기)

1.  **Task 1: 게임 호스트(Game Host) 구현 (우선순위: 최상)**
    - 새로운 Python 스크립트(`game_host.py`)를 생성합니다.
    - 이 스크립트는 `lobby.py`의 `/spawn_agent` API를 호출하여 필요한 수의 AI 에이전트를 생성합니다.
    - 분산 키 생성(DKG) 절차를 조율합니다.
        - 각 에이전트의 `/dkg_setup`, `/dkg_round` 엔드포인트를 순서대로 호출합니다.
    - 기본적인 낮/밤 사이클 로직을 구현합니다.
2.  **Task 2: 기본 투표 기능 구현 (우선순위: 높음)**
    - 게임 호스트에 위 `3.2. TODO` 섹션에서 설계한 암호화된 투표 절차를 구현합니다.
    - 각 에이전트의 `/request_action`을 호출하여 암호화된 투표 벡터를 받고, 이를 합산하여 공동 복호화 절차를 통해 결과를 도출합니다.
3.  **Task 3: 기본 승/패 조건 구현 (우선순위: 보통)**
    - 매 사이클이 끝날 때마다 호스트가 승리/패배 조건을 확인하는 로직을 추가합니다.
    (예: 마피아 수 >= 시민 수)
4.  **Task 4: 경찰 능력 구현 (우선순위: 보통)**
    - `3.2. TODO`에 기술된 대로 경찰의 조사 능력을 구현합니다.
    - 조사 결과는 경찰 플레이어만 볼 수 있도록 암호화되어야 합니다.

이 설계 문서를 바탕으로 위 로드맵에 따라 개발을 진행한다면, 프로젝트를 실제 플레이 가능한 상태로 빠르게 발전시킬 수 있을 것입니다. 가장 중요한 것은 **게임 호스트**의 구현임을 다시 한번 강조합니다.
